## The owner's core-object ruling — the DATABASE-side backbone (proposal written)

**Owner's point (verbatim intent):** *"it is important to look at core architecture from the database side
as well (which is even more important). In a platform where users can customize database, there are
tables/columns/relationships that should not be editable because they are the backbone of the schema and
editing it can crash the system."*

**The correction I had to make (and it matters):** there are **two axes**, and `SD-2` built only one.

| Axis | Harm | Vector | Guard |
|---|---|---|---|
| **A — row-level** | an object is **deleted** (the `superadmin` role) | `DELETE` on a row | **`SD-2` — BUILT** |
| **B — structural** | the **schema backbone is changed** (table dropped, column removed/re-typed, relation broken) | customization UI / S2 gate / Hermes-proposed change | **NOT built** — the owner is asking about this one |

**Measured (live PG 17, `open-mercato`):** 143 tables, 112 ORM entity definitions; populated starter data:
tenants 1, organizations 1, users 3, roles 3, role_acls 3, user_roles 3.

**Three prior-art lists already exist, none answering "may this be changed at all":**
1. `shared/src/lib/entities/system-entities.ts` — 7 reserved entity types → **UI selectability only**.
2. `core/.../entities/data/guards.ts:69` — 7 `RESERVED_RECORD_KEYS` → **custom-field column collision**.
3. `shared/src/lib/data/engine.ts:165` (`isOrmBackedSystemEntityId`) → **doc-storage routing** (the
   deepest existing seam; the natural one to extend).

**The measured hole:** a custom field can be attached to a system table — the only block is the 7-id
selectability list, and `users`, `roles`, `tenants`, `sessions` are **not in it**. Nothing covers a DROP or a
broken FK.

**Recommendation written up in `library/development/DECISION-core-object-set.md`:**
- **Tier 1 (core now, ~25 tables):** tenants, organizations(+edges), users/user_roles/user_acls,
  roles/role_acls, sessions/password_resets/api_keys, action_logs/access_logs, the customization substrate
  (custom_entities*, custom_field_*), the index/search tables, module_configs, the migration ledger.
- **Tier 2 (core by default, releasable by a platform release):** authority_*, feature_toggles, webhooks,
  scheduled_jobs, workflow_definitions, record_locks, encryption_maps, perspectives/sidebar_variants.
- **Tier 3 (NOT core):** business data + packs (customers, catalog, sales, wms, staff…) — governed by `SD-1` + `SD-4`.
- **Columns/relations rule:** for Tier-1 tables, system columns (`id`, `tenant_id`, `organization_id`,
  `created_at`, `updated_at`, `deleted_at`) un-removable/un-re-typable; FKs fixed.
- **Sizing:** widen the registry (small) + widen `isSystemEntitySelectable` (small) **now**; the structural
  `MutationGuard` (medium) scheduled with `SD-4` (S5: one engine, not two).
