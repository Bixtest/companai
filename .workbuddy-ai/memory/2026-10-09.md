**Owner's ruling (verbatim intent):** *"we follow your recommendations concerning that. However, analyze if

**Answer: yes — and the platform already contains the exact pattern.** `SD-3` did this one turn earlier for

**The split (and the owner's wording already respects it):**
- **SETTING (Ring 2):** the object→tier map; the default tier for an unmapped object; the system-column set;
  the reserved-entity-type set. A superadmin edits these from the UI.
- **CODE (Ring 1, `CORE-BOUNDARY.md` §2):** the *rule* that a `core` object cannot be deleted or
  restructured; the four tier names; the fail-closed parser. *A setting can move an object BETWEEN tiers;
  it can never DELETE the tiers.*

**The four tiers:** `core` (Ring 1) · `platform_release` (protected from users) · `tenant_structural` (S2
gate + SD-4 grammar) · `tenant_data` (ordinary RBAC). My earlier Tier-1 rec = the seed's `core` rows;
Tier-2 = the seed's `platform_release`; absence = the default `tenant_structural`.

**It corrected a real defect in my first recommendation:** hardcoding the ~25 tables would have meant a
**deploy to protect a table the superadmin just created** — wrong for a customizable platform.

**Honest note:** `SD-3`'s own setting has **no UI yet** (measured: only `configs/cli.ts` writes it). So the
manage screen for the core set folds into **`SD-5`** (one per-object grid, two settings), not a second UI.

## LESSON — never edit a CRLF file by a line number taken from another tool (near-miss, register damaged 32 lines)

**What happened.** To mark CC-25 DONE in `COMPLETION-CALLBACKS.md` I did `grep -n "CC-25"` → saw
"line 44", then ran a Python script that replaced `lines[43]`. **But line 44 of the file is the heading
`## The register`, NOT the CC-25 row** — because `grep` and Python **disagree on line numbering in a
CRLF file**, and my `.tmp` was LF while the file was CRLF. The result: I overwrote a heading, which
merged two sections — **177 lines became 145**, and the reconciliation silently dropped **39 rows → 36**.

**How it was caught.** The register's own reconciliation count changed (39/22/17 → 36/20/16). A count
that moves when you only touched ONE row is the alarm. **Restored immediately** with
`git checkout -- library/development/COMPLETION-CALLBACKS.md`, md5-checked back to `12eab558…`.

**The correct method (now the rule).**
1. **Locate the target by CONTENT inside the same pass that writes** — never a line number from a
   different tool. `[i for i,ln in enumerate(lines) if ln.startswith('| **CC-25** |')]`, assert exactly
   one match.
2. **Work in the file's OWN line-ending domain.** `grep CRLF` first: `python -c "print(open(p,'rb').read().count(b'\r\n'))"`.
   The register is **CRLF 177** (unlike JOURNAL/BUILD-ORDER/BACKLOG which are LF-0). So `text.split('\r\n')`
   and `'\r\n'.join(...)`, and normalise the injected string's endings to match.
3. **Assert the invariants in the same pass** — row count + CRLF count — not in a separate command after.
4. **A one-row change must show `1 insertion(+), 1 deletion(-)`.** Anything more is collateral damage.

**Also learned: the register's real row shape is 5 CONTENT cells** = 7 awk parts
(`| ID | Gap | Prerequisite | Trigger ↔ checked at | Callback |` + two empty edges). The `BAD-COLUMNS`
check counts only ` | ` (space-pipe-space) ≥ 4 — escaped `\|` inside cell text inflates `awk -F'|'` field
counts, so **do not** use raw field count as the shape test.

**CC-25 closed:** 39 rows / **21 open / 18 done**; CC-25 now a canonical 5-cell row marked ✅ DONE.
