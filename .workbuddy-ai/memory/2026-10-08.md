## `SD-1` — the S2 permissions gate: the decision core is built; the enforcement half is NOT. **PARTIAL.**

**Fact-check (step 4).** SD-1 is not "build the resolver" and not "add a table" — it is **the permissions
question made unskippable**. Measured: **no permission catalogue exists** (grep for
`permissionCatalogue`/`permission_record` → 0 files). Permissions are `features_json` string arrays on
`RoleAcl`/`UserAcl` (`auth/data/entities.ts:272/307`); the check is a pure string match
(`shared/src/security/features.ts`). Two things DO exist and were reused (S5 — one engine): the
**capability registry** (`shared/src/lib/capabilities/registry.ts`, declared descriptors from each module's
`acl.ts`) and the **per-entity synthesized records** (`entities/lib/recordFeatures.ts` →
`entities.records.<entityId>.view|manage`, aggregated by `auth/api/features.ts` +
`restrictedEntityFeatures.ts`). The change path is the **MutationGuard socket**
(`beginEntitiesMutationGuard` → `runRouteMutationGuards` → `runMutationGuards`).

**The constraint that shaped the design.** DB-backed code is tested against a **mocked EntityManager**, so
a migration is **unprovable on this host** (`user-function/document.ts:22-28` states the same reasoning).
So the catalogue is a **typed `shared` service**, not a new table — like the metadata registry.

**What was built.** `shared/src/lib/permissions/catalogue.ts` (surfaces + the two blocks each yields: data
`view`/`manage` + structural `structure`; `declareSurfaces`/`recordSurface`/`permissionRecordsFor`/
`hydrateCatalogueFromFeatures`) and `structure-change-gate.ts` (`evaluateStructureChange` → `decided |
defaulted | refused`, pure, fail-closed: `no_surface` / `malformed_surface_id` /
`unrecognised_surface_kind` / `empty_decision`; `DEFAULT_GRANT_ROLE='superadmin'`). Hook: two
`MutationGuard`s on `entities.field_definition` / `entities.entity` `create` in `entities/data/guards.ts`,
registered in the exported `guards` array.

**Verification.** 37 new tests. **8 mutations RED-then-GREEN**, each restore **md5-verified byte-identical**
(bytes I/O — the LF→CRLF trap bit a scripted restore twice, caught both times by the md5 check).
`shared` **197 suites / 2327**; `core` **618 suites / 5332**; typecheck **0** (both packages).

## `SD-1` step 1 — the WRITE: the gate is now an enforcement (was the headline limit)

**The gap closed.** SD-1's headline limit was *"a gate that decides but does not record is not yet a gate."*
Step 1 of `PLAN-SD-1.md` §10 is now built: the gate's `defaulted` records are **written** into the tenant's

**Fact-check (step 4) — what the write needed.** The ACL store's write path is

**What was built (code repo).**
