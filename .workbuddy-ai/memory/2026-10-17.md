## Bugs found in my own code while building (all three in the dangerous direction)

1. **The check reported *itself* as a consumer of `.delegable`** — the registry's own
   `consumer: /\.delegable\b|\[['"]delegable['"]\]/` contains a quote inside a character class, which
   `strip()` read as a string delimiter; the `\.delegable` before it survived and matched. A dead
   control read **COVERED**. Fix: rewrote `strip()` to handle **regex literals**, tracking `lastSig` to
   disambiguate regex from division (after an identifier, number, `)` or `]` a `/` is division;
   `}` counts as a literal opener) and respecting `[...]` classes where `/` is ordinary.
2. **Prose inside `note:` strings read as declarations** — `auth/acl.ts:112` carries "Emphatically not
   itself delegable:". A raw grep reports 29 declaration sites; the true count is 24 (five are prose).
   Fix: the string-stripping layer of `strip()`. The 29-vs-24 discrepancy is recorded as a MEASUREMENT
   NOTE so nobody re-derives the wrong number.
3. **`__tests__` was in `SKIP_DIRS`, so test files were never walked** — `testConsumers` was
   structurally always 0, making "exercised only by its own test" indistinguishable from "never
   exercised". Fix: split into `ALWAYS_SKIP` and `TEST_DIRS` with `walk(dir, out, includeTests)`.

Also fixed: the C6 control had no `declaration` regex so its own signature inflated the consumer count;
`demoteIfEvidenceDemands`'s loose declaration regex matched the four test call sites (anchored it to
line start); mutation B was a bad mutation, not a weak test (changed to `if (false)` and added a sixth

### T-01 — the delegation route no longer lends authority the lender does not have (`fa974bb1`)

Three checks in `packages/core/src/modules/auth/api/authority/delegations/route.ts` before
`delegations.grant`, **one more than the triage's fix sentence named**:

1. **grantor-holds** — the caller must actually hold the capability they are lending. The triage named
   the descriptor read, the `delegable: false` refusal and the self-delegation ceiling; this check
   extends the route's own header principle ("nobody may lend authority they do not hold") from the
   *grantor id* to the caller's *own holdings*. Without it the literal three-part fix would still let a
   caller holding only `auth.delegations.manage` lend `api_keys.manage`.
2. **`delegable: false` refuses even a holder** — closes `auth.delegations.manage`'s own
   chain-of-delegations failure mode.
3. **self-delegation needs an explicit ceiling** — a delegation is an independent authority source at
   use time (the resolver reads the record, not the grantor's current ACL), so a self-delegation with a
   null ceiling outlives the holdings that justified it.

Proof: 9 tests in `delegations.route.test.ts` driving the real handler with service doubles; 3
mutations run for real, each killing exactly its own test. **The decisive assertion in every refusal
case is that the write never happened** — `delegations.grant` was never called, not merely a 403 after
it. 216 tests across all 18 auth API suites; tsc + eslint clean.

Bugs in my own work while building: a test used `id: 'd1'` where `revokeSchema` requires a uuid (400
not 200); the commit message claimed the triage named the wrong subset of my checks — amended
`5a486018` → `fa974bb1` with the correction (rule 13).

### T-02 — `business_ir.run_query` no longer reads an entity the caller has no permission for (`60a6714f`)
