### ★ The design insight that makes the build small
The invoker half splits in two: **holding** (`holdsCapability(person, feature)` — a feature-id
question, **no descriptor needed**) and **gating** (A0–A5 — needs one). `invokerCeilingFor` returns
early on `!capability` (`:495`), so holding is never asked for the 36. Asking it directly closes the
intersection rule for **all 157** without writing 36 descriptors.

### ★ A cycle that terminates only by coincidence
`di.ts:59` implements `holdsCapability` as `rbac.userHasAllFeatures(...)` — which calls
`refusedByAuthority` → `refusalFor` → `decideFor` → `invokerCeilingFor` → `holdsCapability`.
It stops only because `refusalFor` passes **no** options, so the inner call returns `null` at `:497`.
Any change that supplies an invoker unconditionally = infinite recursion. Requirement R4 is gated on
*an invoker being present* for exactly this reason.

## Research: how to make the communication rule hold

`library/development/ANALYSIS-2026-10-19-owner-communication.md`. Research done across the 11
studied platforms, the web, and synthesis. **No new `CC-*` row** — this is a rulebook improvement.

**Donor harvest, and only one donor had anything:** **Zulip** — `.gitlint` + `tools/commit-message-lint`
(lints message **shape** in CI: ≤72-char title, capital, full stop), `commit-discipline.md`
(*"a message that reads like a list of dissimilar things should have been several commits"* — the
batching diagnostic), `how-we-communicate.md` (*explain the reasoning behind a request*),
`asking-great-questions.md` (**"try, then ask"** = the owner's default rule). **The other ten
(Hermes, Multica, Buzz, Paperclip, CrewAI, Gastown, n8n, OpenRig, Activepieces, Mattermost) carry
nothing on this subject — saying so is part of the finding.**

**Standards:** ISO 24495-1:2023 (relevant · findable · understandable · usable — plain is defined by
the reader's ability to act, not vocabulary level); US federal guidelines (active voice, present
tense, short sections, **hidden verbs**); BLUF / Minto Pyramid (answer first); Amazon narrative +
PR/FAQ (banned slides because they hide an unclear idea); Nygard ADR (status · context · decision ·
consequences, and the value is that it is **dated**).

**★ The thesis:** the rule fails because it is **advice about style**, and style cannot be checked.
Zulip's lesson is to **separate what can be checked (shape) from what cannot (tone)** — it lints
length and punctuation and never attempts tone. So: a **five-slot message skeleton**
(what changed · why it matters · how I checked · waiting on you · next), identifiers **banned from
slots 1–2** and welcome in slot 3, a **translation table as data**, and a **dated amendment log**.

**★ The best idea in it:** *jargon is a diagnostic, not a style fault.* If the sentence stating the
consequence needs a mechanism word, the consequence has not been decided yet. That converts an
unenforceable style rule into a thinking rule — and it is the same claim the note already makes about
diagrams.

**Applied:** the skeleton + question template + translation table (my own output, reversible), and
the §2.3 scope fix (it still said "a QUESTION" while the top note had been widened — a contradiction
I created). **Waiting on the owner:** whether the five-slot shape becomes the required form in
`WORKING-RULES.md`, with the log beside it. Default if silent: yes.

## CC-132 — requirement written (`78e0753` docs · `938d1c66` the measurement instrument)

**No code.** Per the standing rule, the requirement came first: `PLAN-CC-132-coverage-guard.md` §3
(R1–R8) and §5 (7 mutations).

**What changed in my understanding.** The row said the guard "measures one package and reports 100%".
That is one defect. Measuring found **three**, all in the same twelve lines of
`capability-coverage.test.ts`:

1. **The numerator reads one directory.** `modulesRoot` is `packages/core/src/modules`, so a module
   shipped by any other package is absent from **both** halves of the fraction — which is why the
   fraction reads 100% and why nobody noticed.
2. **The denominator is parsed from a file that holds more than one list.** The scan takes every
   `id: '…'` literal in `apps/mercato/src/modules.ts`, so it reports **36** enabled ids where the array
   holds **35** — the extra is `example`, which that file says is *deliberately off*. So the fraction
   was wrong in **both directions at once**.
3. **The enabled set is not static.** Three more entries are pushed at run time: `example` +
   `example_customers_sync` under `OM_ENABLE_EXAMPLES`, `storage_s3` under `OM_ENABLE_STORAGE_S3`, and
   everything in `officialModuleEntries` (empty today, will not stay empty). **A parse that stops at the
   array literal is correct today and silently wrong the first time somebody sets a documented flag —
   this row's own defect, one level up.** That is what makes the fix's shape: the parse must be able to
   **fail on an enablement path it does not know**.

**The number moved twice, both recorded (Rule 13).** Carried: 157 enabled / 121 described / 36
undescribed. Measured: **default environment 149 / 121 (81%) / 28 across 7 modules**; **every documented
flag on 160 / 121 (76%) / 39 across 10 modules**. The build must close **39**, not 28 — a check that
goes red on a supported configuration is a check people switch off.

**A trap found before any fix was written.** `example` exists **twice** — `packages/create-app/template/`
and `apps/mercato/`. So the obvious fix ("walk every package for `acl.ts`") **double-counts the template
copy**, describing a template that ships to generated apps. Resolution must be by each entry's own
`from`, never by a directory walk. Measured, not assumed.

**One stale requirement found.** A tool requires `customers.people.view`, and `customers` is **parked** —
so the feature is not declared in any enabled module. That is a question about which tools ship, not
about coverage; recorded in the plan §6 so it is not rediscovered.

**The judgement calls are defaults, not questions.** Eight classifications are genuinely arguable
(`ai_assistant.mcp.serve` → E3, `webhooks.secrets` → E5, `scheduler.jobs.trigger` → E3, …); all are in
§4.3 with the argument against each, so if one is wrong it is wrong by name. The tie-break is the
codebase's own rule — *classify by the worst act it permits* — plus **when in doubt, classify higher**,
because over-classifying costs an agent some autonomy and under-classifying lets a destructive act run
unattended.

### `CC-128`'s requirement — and measuring corrected the row twice

`PLAN-CC-128-tenant-ceiling.md`. No code (standing rule). Two corrections, both by name:

1. **The row's premise was too strong.** *"No plan/feature/limit/settings table exists"* — a settings table
   **does**: `module_configs` is a **three-level** store (platform → tenant → organization) with a nullable
   `tenant_id` and two partial unique indexes. The platform/tenant split this row needs is **already in the
   codebase**. What is missing is a **ceiling model**, not a place to keep settings.
2. **The defect is more precise than "no ceiling".** `UserAcl.tenant_id` is `uuid NOT NULL` with the comment
   *"Tenant scope is mandatory for ACL evaluation"*, and `isGlobalSuperAdmin` (`rbacService.ts:247-275`)
   queries `UserAcl` with **no tenant filter** — so one tenant's superadmin is every tenant's.
   **The data model is tenant-scoped and the read is not.**

**★ The design was settled by a rule already in the codebase, not invented here.** `featureMatch.ts:25-43`
is headed *"Do NOT build a feature-list intersection on top of this"*, lists six ways a permission set is not
a list, and ends *"the intersection must be of answers, not of lists"*. That was written for `CC-123`. So the
capability ceiling is a **third input to the resolver** (after the autonomy gate and `CC-123`'s invoker),
**never** a filter over `acl.features`. A list intersection would deny a `['*']` holder everything and lose
every `prefix.*` family — all six cases are live here.

**★ And a naming collision caught before it reached a table:** *ceiling* already has **two** live meanings in
this codebase — the autonomy gate (A0–A5, from organization edges) and `CC-123`'s invoker. This is a
**capability** ceiling, and the table is `tenant_capability_ceilings` so the name says which one.

**Shape chosen, with the alternative named:** one row per capability (not a JSON array), because the
subset rule becomes a `NOT EXISTS` instead of a parse-and-guess, and because a removed capability is a
visible deleted row — the audit trail §4.6 asks for. `tenants.is_foundational` as a **boolean with a
one-row partial unique index**, not a parent link: A must stay a strict subset of B's shape so `CC-133` is
additive.

**Named as a debt, not smuggled in:** `isGlobalSuperAdmin`'s missing tenant filter. Bounding its consequence
(R2) is not the same as changing the read, and that read has callers.
