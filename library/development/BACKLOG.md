## §A — The re-measurement, so the `★ Hermes:` rule cannot rot

**The rule** (stated in the header, and in [`WORKING-RULES.md`](WORKING-RULES.md)):
[`ARCHITECTURE-hermes-service-map.md`](ARCHITECTURE-hermes-service-map.md) **is the starting thread in
any task development**, and **every AI-touching item in this file carries a `★ Hermes:` line** naming
the map section that says how Hermes serves it or is served by it.

**Why a command and not a promise.** This was **measured broken on 2026-10-06**: the map named **43**
item IDs, and this file named the map **0** times — so a developer reading `AH-9` or `G-06` was never
told the Hermes relationship existed. A rule with no test is the same defect one week later.

**The check — every item the map names must be reachable both ways.**

```bash
cd /c/Users/Ramzi/Downloads/companai/library/development
# The item IDs the map names in Part I (§4.1–§4.4), deduped:
MAP_IDS=$(sed -n '139,279p' ARCHITECTURE-hermes-service-map.md \
  | grep -oE '\*\*(SD-[0-9]|G-[0-9]+|S-0[0-9]|AH-[0-9]+|ML-[0-9]|N-[0-9]+|V-[0-9]+)\b' \
  | tr -d '*' | sort -u)
# A match is any line whose OWN text carries both the item and a ★ Hermes: marker.
# The marker may ride a bullet item or a table row — so this greps the line, not a bullet prefix.
for id in $MAP_IDS; do
  grep -qE "\*\*$id\*\*.*★ Hermes:|\*\*$id\*\*.*hermes-service-map" BACKLOG.md \
    && echo "OK      $id" || echo "MISSING $id"
done
# The V-09/V-13 and the '7 V-HOLDs' shared row print MISSING above because the marker sits on the
# group row, not the id. Verify that row by hand — it is one line:
grep -n "V.HOLDs" BACKLOG.md | grep "★ Hermes:"
```
**Result on 2026-10-06 after this change: 41 of 43 print `OK`; the other 2 (`V-09`, `V-13`) are named
on the shared `7 V-HOLDs` row, which carries the marker and prints on the last line.** Net **0 real
misses**. This file now names the map **66** times, up from **0** — measured with
`grep -c "hermes-service-map\|★ Hermes:" BACKLOG.md`.

**The second half of the rule — the reverse.** Every AI-touching item must be reachable **from** the
map too, so the two cannot drift apart in the other direction:

```bash
cd /c/Users/Ramzi/Downloads/companai/library/development
# Every AH-, ML-, SD-, G-, S- item in BACKLOG that is AI-touching must be named in the map:
grep -oE '^\s*-\s*\[[ x]\]\s*\*\*(SD-[0-9]|G-[0-9]+|S-0[0-9]|AH-[0-9]+|ML-[0-9]|N-[0-9]+|V-[0-9]+)\*\*' BACKLOG.md \
  | grep -oE '\*\*.*\*\*' | tr -d '*' | sort -u \
  | while read id; do grep -q "\*\*$id\b" ARCHITECTURE-hermes-service-map.md \
      && echo "IN MAP  $id" || echo "NOT IN MAP $id (either AI-touching work is undocumented, or it belongs on the map's 'Not in this map, and why' list)"; done
```

**When this fails, the fix is one of two things — never silence:** either the item's map row is
missing (add it to the map, §4.4), or the item is genuinely not AI-touching and its name belongs on
the map's **"Not in this map, and why"** list. **An item with no Hermes relationship and no line
saying so is the defect this whole section exists to catch.**
