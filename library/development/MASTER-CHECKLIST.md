## 11. Keeping it current — measured, not trusted

**The rule, in one line: change a status, then run the checkers.** Both live in the **docs** repo —
from this folder they are `../../scripts/…`, not the sibling code repo's `scripts/`:

node ../../scripts/derive-counts.mjs             # re-derives 78/321 from platform_points.md's boxes

**36 checks, seventeen of them added on 2026-10-17 (night)** — the previous five could not see a stale
status tally, a mis-sorted table, a duplicate row, a code pipe that broke a table, or a single id from
another register.

**The checker is itself proven, not assumed** — `../../scripts/__tests__/check-master-checklist.mutations.mjs`

**★ And the proof found a hole in the proof — three times.** The first run's **M11 came back GREEN**:
a renamed row that no check caught, because a sort comparison cannot see a duplicate. The check was
added and the mutation turned red. Then the **table-shape check itself was wrong**: it called a
single-backslash `\|` a live pipe, so the document's own correct escapes read as defects and the real
over-escape read as fine. **M13 exists to keep that one honest.** And the third, found tonight while
closing `CC-101`: **three mutations came back GREEN because their target text had gone stale** — the
document's numbers had moved (54 open → 56, 13 startable → 15) and `String.replace` on a missing
target is a **silent no-op**, so the file went in unchanged, the checker passed, and the suite printed
three proofs that never happened. **A proof that cannot fail is worse than no proof** — the same
finding as `CC-101`, one layer down, in the instrument rather than the thing it measures. The harness
now fails any mutation that leaves the file unchanged, and **M14** keeps the other half honest: the
headline check had been reading §2's copy of the register count instead of §5's, so breaking §5's
number was invisible. A test that has never been allowed to fail is not yet a test — and a check
that has never been shown wrong is not yet a control.

**Why a script and not a habit:** the last version of this file was kept in sync by hand with a second
copy, and the drift was found by reading, not by running. A habit drifts; a check that runs every time
does not. **`ci.yml:499` and `:509` are currently the only two checker invocations of seven** — that is
`CC-101`, and when it lands these two join them, so a stale number breaks the build instead of quietly
being believed.

**★ Honest state, per the rule this file keeps re-learning: neither script is wired into anything yet.**
Nothing calls them — not CI, not `.husky/pre-commit` — so today they are **built but not enforced**,
which is precisely the `CC-101` defect in miniature. They are recorded that way on purpose rather than
counted as a control that works.
