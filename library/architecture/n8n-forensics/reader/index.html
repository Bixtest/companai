n8n Study — Batch 00: the pin, the method, and what this study is#

Folder: library/architecture/n8n-forensics/ · Status: OPEN — begun 2026-10-15 This is a clean forensic study, run the same way as hermes-forensics/, paperclip-forensics/, crewai-forensics/, multica-forensics/ and gastown-forensics/. It reads ONE source tree, measures it, and verifies every load-bearing claim against the source code. Nothing from any earlier study is reused, referenced, or assumed — n8n is read on its own terms.

Why this platform is sixth. The owner's ruling was "one platform at a time": Paperclip, CrewAI, Multica and Gas Town are closed. n8n is sixth, chosen by the owner because "it is a rich and highly rated platform" — and it is the first platform in this study whose stated purpose is the composition surface itself: a visual canvas where workflows and AI agents are built and run. The four closed platforms were each measured to have no widget/composition model (Paperclip, CrewAI, Multica, Gas Town). If that verdict is about to change anywhere, it is here.

The owner added a directive to this study (§7): identify what fits the vision and what could be taken further. Per the method, the batches stay comparison-free — the "take it further" notes are observations in the synthesis, and the decisions stay the owner's at the mapping pass.

1.1 The extraction lives outside the study folder — and why#

The study's convention is platforms/_extracted/<name>. This study reads C:\n8n instead. The reason is measured, and a later reader must not mistake it for carelessness:

  • the conventional destination is 87 characters deep before any filename;
  • n8n's longest paths reach 209 characters relative, i.e. ~296 absolute;
  • Windows' default MAX_PATH limit is 260.

Extracting into the deep workspace path therefore wedged at the first path over the limit (a background unzip froze dead at 16,624 files with nothing written for minutes). The owner extracted manually to a short root path instead, and the result verified exact. To reproduce this study, extract the zip to a short root path — C:\n8n is what was used — not into the workspace.

⚠️ platforms/_extracted/n8n-main/ is a KNOWN-INCOMPLETE ARTEFACT and must not be used. It holds the 16,624 files written before the stall. It is a partial copy of C:\n8n; reading it instead of C:\n8n would silently produce findings about a truncated tree. It is left on disk rather than deleted (deleting is destructive and was not requested) — if it is ever removed, nothing in this study depends on it.

1.2 The identity limit (stated, not glossed)#

There is no .git, so the exact upstream commit cannot be read from the tree. Any claim here about "the latest n8n" is a claim about this extract. The module is n8n-monorepo and the binaries are n8n / n8n-worker (verify in batch 01).

3. The method (how every batch is produced)#

The method is inherited verbatim from the five closed studies (rules 1–10), with the pole frame (§3.1) and the additive-across-studies rule (§3.2) as before.

  1. Docs are claims; code is the authority. Every load-bearing statement is checked against the source. Where they disagree, the code wins and the disagreement is recorded.
  2. Every number is measured at the time of writing, never carried from memory or an older document.
  3. Claims carry their evidence: a line resting on code cites the file and line it was read at.
  4. Two value questions per capability: Q1 · USER VALUE (how it serves a person using the platform) and Q2 · VISION VALUE (how it serves the AI-first business & resources planner vision, incl. versatility and integratability).
  5. No comparison to our own platform inside the batches. The cross-platform mapping is a separate later pass.
  6. Every capability is named, including ones we will not use. Nothing is silently dropped.
  7. Findings are additive and never overwrite history.
  8. Plain words — every capability gets a one-sentence plain gloss before any detail.
  9. THE POLE FRAME. Every finding is tagged P1 / P2 / P3 / PX-W / PX-F / PZ.
  10. The retirement rule. Before reusing any setting/key/module named in an older document or another platform's doc, search this platform's config/CHANGELOG for a retirement entry. n8n has a 2 MB changelog, so this rule has an unusually rich surface here.

3.1 The pole frame — the three poles, defined once#

Tag Pole The owner's words (abridged)
P1 The aissistant (the AI user / agent) versatile, integratable, rich featured architecture in itself, deployable in different contexts (workspaces, automations, later the studio)
P2 The workspace highly functional, versatile, integratable, rich featured, adaptable to the mix of current and future features, use-cases and needs
P3 Automations where agents work on assigned tasks, assign tasks, etc. Paperclip is a blueprint
PX-W Widgets architecture cross-cutting: the composable UI surface
PX-F Frontend wiring & construction cross-cutting: how the surface is built and wired

Plus one escape hatch (PZ): "any other findings you identify there that can fit our vision, project, architecture, or a potential use case or added value for the end user." Tagged PZ with a one-line reason for keeping them.

3.2 Additive across studies, like rule 7 within a study#

This study does not rewrite the five closed studies. Where an n8n finding confirms, contradicts or extends an earlier finding, it is recorded as a cross-study note naming the earlier batch — so a reader can trace both directions. Cross-study notes are observations, never decisions.

5. The owner's directive for this study (§7)#

The owner asked two things that shape the synthesis:

  1. What fits the vision — answered per capability in the batches and ranked in batch 07.
  2. What could be taken further — recorded as observations in batch 07 §7, never as decisions.

The method's discipline still holds inside the batches: rule 5 (no comparison to our own platform) applies to batches 01–06. The synthesis (§7) may name a mechanism as extensible — e.g. "this pattern would allow X" — but it must stop at the observation. The mapping pass and the owner decide.

And the licence gate from §2.5 travels with every observation: nothing here is a right to copy. The .ee files are unlicensed; the Sustainable Use License restricts commercial use. Read the architecture; reimplement what is worth having.

6. Ground rules restated as a checklist the reader can hold this study to#

  • Is the claim measured, or remembered? → must be measured.
  • Does the line rest on a doc, or on code? → code, always.
  • If doc and code disagree, is the disagreement recorded? → must be.
  • Is every capability named, including the ones we will not use? → must be.
  • Is every finding tagged with its pole (P1/P2/P3/PX-W/PX-F/PZ)? → must be.
  • Are the two value questions answered in the owner's words? → yes, per capability.
  • Is there any comparison to our own platform in a batch? → must be none; that is the later mapping pass.
  • Before reusing an older-doc setting, was the retirement rule run (rule 10)? → must be.
  • Does the line count say whether it includes tests? → with 32.8 % of .ts files being tests, every count in this study states its basis.
  • Is a .ee file being treated as available? → it is not; §2.5 governs.

4. **Two value questions per capability**: **Q1 · USER VALUE** (how it serves a person using the platform)
   and **Q2 · VISION VALUE** (how it serves the AI-first business & resources planner vision, incl.
   versatility and integratability).
5. **No comparison to our own platform inside the batches.** The cross-platform mapping is a separate
   later pass.
6. **Every capability is named, including ones we will not use.** Nothing is silently dropped.
7. **Findings are additive and never overwrite history.**
8. **Plain words** — every capability gets a one-sentence plain gloss before any detail.
9. **THE POLE FRAME.** Every finding is tagged **P1 / P2 / P3 / PX-W / PX-F / PZ**.
10. **The retirement rule.** Before reusing any setting/key/module named in an older document or another
    platform's doc, **search this platform's config/CHANGELOG for a retirement entry.** n8n has a
    **2 MB changelog**, so this rule has an unusually rich surface here.

### 3.2 Additive across studies, like rule 7 within a study

## 6. Ground rules restated as a checklist the reader can hold this study to

- Is the claim measured, or remembered? → must be measured.
- Does the line rest on a doc, or on code? → **code, always.**
- If doc and code disagree, is the disagreement recorded? → must be.
- Is every capability named, including the ones we will not use? → must be.
- Is every finding **tagged with its pole** (P1/P2/P3/PX-W/PX-F/PZ)? → must be.

  every count in this study states its basis.
