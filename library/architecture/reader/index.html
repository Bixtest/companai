3. The method (how every batch is produced)#

This is forensics, so the discipline is fixed and stated up front:

  1. Docs are claims; code is the authority. Every load-bearing statement a doc makes is checked against the Python source. Where they disagree, the code wins and the disagreement is recorded as a finding.
  2. Every number is measured at the time of writing, never carried from memory or from an older document. File counts, line counts and hashes are produced by a command and quoted with their result.
  3. Claims carry their evidence: a batch line that rests on code cites the file and line it was read at.
  4. Two value questions per capability, per the owner's instruction:
    • Q1 · USER VALUE — how does this serve a real use case for a person using the platform?
    • Q2 · VISION VALUE — how does this serve the vision of an AI-first business & resources planner, now and long-run, including versatility and integratability?
  5. No comparison to our own platform inside the batches. Understanding first; comparison is the synthesis's (Batch 12) job alone.
  6. Every capability is named, including ones we will not use. Nothing is silently dropped.
  7. Findings are additive and never overwrite history: a later batch that changes an earlier batch's line says so explicitly rather than editing it away.
  8. Plain words — every capability gets a one-sentence plain gloss before any detail.
